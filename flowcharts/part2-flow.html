Part 2: Top Terms, step by step

What Claude does during Part 2 of the retrieval activity, how it does each step, and why the step is there. Part 2 shows which words TF-IDF treats as most distinctive in a movie's plot summary, using the settings the student chose in Part 1.

Time: about 6 minutesStarts after: commit Part 1 doneEnds with: commit Part 2 done
Claude acts Student decides
  1. 1

    Check the tools are installed

    Claude acts
    How

    Reads the log of the setup job that ran in the background, looking for uv's line Installed 38 packages or Checked 38 packages. If the log is missing, runs uv sync.

    Why

    top_terms.py needs scikit-learn. The embedding model can still be downloading; Part 2 doesn't need it.

  2. 2

    Ask for two movies

    Student decides
    How

    Asks one question: which two movies do you know well? The movies rated in HW1 are in the 4,309-movie collection.

    Why

    The student can only judge whether a word is "distinctive" for a movie they actually know. Two fits in class; more is fine at home.

  3. 3

    Run top_terms.py for each movie

    Claude acts
    How

    Runs uv run python top_terms.py "<title>" with the student's own words. The script builds TF-IDF over every plot summary with the Part 1 settings, finds the title (exact, then without the year, then any title containing it), and sorts that movie's row of weights.

    Why

    It turns the abstract formula into something concrete: the 15 words this model weighs most for a movie the student knows, and how often each appears here and across all summaries.

    If the title matches no movie or several: Claude pastes what the script printed (close matches, or the list) and asks which one they meant. It does not guess.

    Inside top_terms.py

    What the script does in one run, in order. It uses code from retrieval.py and scikit-learn.

    1. a
      Load the collection. Reads data/movies.jsonl: 4,309 movies, each with its plot summary from TMDB. IDF compares one summary to all the others, so it needs the whole collection.
    2. b
      Read the settings. Loads REMOVE_STOP_WORDS, MIN_MOVIES and REPEATS_COUNT_LESS from tfidf_settings.py and checks each value is allowed. These are the student's Part 1 choices; search and evaluate read the same file.
    3. c
      Build the TF-IDF matrix. scikit-learn's TfidfVectorizer lowercases every summary, splits it into words, applies the three settings (stop_words, min_df, sublinear_tf), then fit_transform makes one row per movie and one column per word. A word's weight goes up the more often it appears in this summary (TF) and the fewer summaries contain it (IDF). Each row is scaled to length 1. This is the model the student configured, built fresh on every run.
    4. d
      Find the movie. Tries the exact title, then the title without its year (so "the matrix" finds "Matrix, The (1999)"), then any title that contains the words. None or several matches stops here. Students type titles loosely; this finds one movie without guessing.
    5. e
      Rank its words. Takes that movie's row, sorts its weights from high to low, and keeps the top 15. For each word it also counts count here (times in this summary) and movies (how many summaries have it). The two counts show TF and IDF separately, so the student can see why a word ranks high.
    6. f
      Print. The table, a note on the columns, the full plot summary and the settings used. The summary lets the student check each word against the text it came from.
  4. 4

    Paste the output in full

    Claude acts
    How

    Copies the output exactly into a code block: the 15 words, the column notes, the plot summary and the settings line. Nothing shortened or relabeled.

    Why

    The student's terminal hides tool output, so the paste is the only way they see it. Exact copies keep their reading honest.

  5. 5

    Ask what the words get right and wrong

    Student decides
    How

    Asks the slot's question: what do the top terms get right and wrong about what makes each movie distinctive? A sentence or two is enough. If asked why a word is on top, Claude asks what they think first.

    Why

    The interpretation is the learning. Explaining first would hand them the answer, and the writeup is graded on their own words.

  6. 6

    Write their answer into WRITEUP.md

    Claude acts
    How

    Reads WRITEUP.md, replaces the Part 2 slot's XXXX with their words exactly, and shows the slot as it now reads. Tidying is offered as a question, never done silently.

    Why

    Claude is the typist, not the author. Nothing is added or made stronger or weaker.

  7. 7

    Save the part to GitHub

    Claude acts
    How

    Runs python3 dump_transcript.py, stages WRITEUP.md and tfidf_settings.py by name, commits Part 2 done and pushes. A hook blocks the commit if a Part 2 slot still reads XXXX.

    Why

    Progress is saved even if class ends mid-activity, and the commit marks where the next session should pick up (Part 3).

Rules that hold across the part

  • Claude never says which words are "right" or whether an answer looks good.
  • No caveat is added in Part 2, to keep it short.
  • Explaining TF-IDF, the columns, or the code is always allowed when the student asks.
  • One step per turn, one question at the end of each message.
